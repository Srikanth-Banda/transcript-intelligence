1. The task¶

Transcript Intelligence turns recorded calls (support, external, internal) into things different stakeholders can act on. The brief asks for three pieces of analysis and three deliverables:

  • Task 1: categorise the calls by theme with a pipeline, and explain why that approach.
  • Task 2: sentiment across call types, with trends and what they mean, not only charts.
  • Task 3: what else can be seen, for different stakeholders.
  • Deliverables: a slide deck, this reference repo, and a short video demo.

The panel states what it grades: thinking, judgment and the quality of insights, not whether every line was hand-written. So this repo is organised around decisions and evidence: every choice is in DECISIONS.md with its reasons, the rejected alternatives and the known weakness, and each notebook below shows the evidence for one stage.

6. Reproducibility proof¶

A temperature of 0 does not guarantee identical output from these models (measured in notebook 06). What makes the results reproducible is the committed cache of raw model responses: each stage is re-run below in replay mode, which reads only the cache (a cache miss would raise an error, never call the network), and the result is compared with the stored output.

7. How to run, and what is original¶

Replay (no key, no network, no cost): uv sync, then open any notebook or run uv run pytest. This is what the notebooks do. Live (to create new cache entries): cp .env.example .env, add an OPENROUTER_API_KEY, set TI_MODE=live, and run PYTHONPATH=src uv run python -m ti.stage1 (and ti.stage2). A changed prompt, model or setting changes the cache key, so it re-runs the affected stage for all calls (decision criterion 6).
